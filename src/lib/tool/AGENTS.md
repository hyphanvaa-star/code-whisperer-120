## Tool rules
- KHB drafts use owner-only `khb_workspaces` with authenticated revision-checked saves via `/api/fpltext/workspace`; `port/khb_persistence.ts` patches the final tool HTML, waits for identity, migrates local drafts, serializes writes, and never deletes an uninitialized/expired draft. Explicit Clear stores an empty draft; file retention and operational matching remain separate so reopening cannot erase work or authorize stale flights.
- KHB and FPL/REQ share `port/cost_index_region.ts` for CI country fallback and explicit airport exceptions, preserving configured CI values. Countries come from the Airport Database ICAO map; unique IATA→ICAO codes are bundled from datasets/airport-codes (OurAirports), never guessed from timezone or prefix, to keep exports consistent.
- NOTAM missing/new quick-view uses `port/notam_change_popup.ts` through the HTML shim; retain PDF bodies and T-60 details alongside comparison state, and acknowledge only opened IDs to preserve later arrivals.
- Compare CREW/REG hover presentation lives in `port/cmp_crew_hover.ts`, separates Excel/FliteBrief without changing matching inputs, labels OFP fallback separately, and imports only its semantic token declarations from global CSS for the isolated tool document.
- KHB change markers reconcile Crewlist through existing reads in `khb_crew_sync`: carry unresolved per-cell markers across pairs, clear completed ones only on a new stable pair, and persist read-back verdicts. Unique full-date/route remapping and request-value snapshots prevent cross-sector or stale green; missing time/crew never proves completion. Refresh identity before optional history reads, repair saved aircraft only with exact diff evidence, preserve manual edits and pending source colors, never reinsert FPL history.
- FPL quick-view reparents the live `wrapVer` into a dialog and restores it on close; acknowledge only a successfully displayed filename so unseen newer revisions remain pending.
- KHB airport cells get a weather warning from `port/khb_airport_wx.ts` using the existing per-place TAF `status` (bad/nil/missing), never new thresholds.
- KHB airport hover composes existing limits and TAF in `port/khb_airport_hover.ts` after the tool-page patches; exempt these cells from generic title tips so weather stays visible.
- NOTAM summaries use per-flight `verdictOf`/`fleetVerdict` in `port/notam_verdict.ts`, not raw map hit counts (those include distant/unresolved/above-ceiling areas). Every FliteBrief NOTAM tracking/fleet place is filtered through `apply24h` before enrichment and counting — the upstream payload is ALL, not the portal's 24H selection.
- GD printing commits paper/orientation, joins disjoint print areas, sets an explicit Zoom measured from the print range (min 18pt margins) and verifies one page via Excel's own PDF export before printing — RICOH drivers ignore FitToPages and Excel's page count can be stale.
- Australian DAH is a bundled snapshot (`data/au_dah.json`: rings + fir + vert) regenerated from the DAH PDF via `parse_australia_dah_areas`; NOTAMs resolve sector names with `au_dah_names_in_text` scoped to the NOTAM FIR, and boundaries following coast/FIR lines are skipped rather than guessed.
- AIP SUP/DAH rings/hours are fetched in `src/lib/tool/aip_sup.server.ts` (parsers in `port/aip_sup.ts`, cache in app_settings `aip_sup:*`), attached as `notam.sup_geoms` by the Check NOTAM handler — NOTAM text often only names the SUP area. JP ENR/KR KOCA use national parsers and country caches; client fixes preserve server arcs and separate areas.
- Named ENR 5.1 areas (WS/WM/WB/VV/VT/VI/RK…) resolve first from bundled `src/lib/tool/data/aip_enr_rings.json` via `port/aip_enr_catalog.ts`; tracking ATS routes use bundled `ats_routes.json` via `/api/notam/vnchart` — live AIP fetches are unreliable in a request.
- Special limits are structured rows (`rule`/`acs`/`apts`) evaluated by browser-safe `src/lib/special-rules.js`, shared by the tool page (via shim) and `port/limits_check.ts`; aircraft groups live in admin-only `limits.acgroups`. Legacy free-text rows keep the old parser.
- Allowed-aircraft LIMIT success is presentation-only via `srOnlyAircraftDisplay` and the tool-page shim; never place success in operational warning arrays, and keep other warnings higher priority.
- Aircraft allowlist airport rules evaluate destination only in the shared special-rules evaluator; departure and alternate restrictions remain independent to prevent unrelated-route warnings.
- Red-triangle verify lives only in the Compare VERIFY column: `port/cmp_validation.ts` prepends a `.cmp-vf` tick wired to `csQuickVerify` (with an `onDone` that clears `ofp_ack` and calls `vMarkDone`), so the flight board callsign cell stays free of write actions; a verify "done" mark expires after `CMP_VF_RECHECK_MS` while FliteBrief still reports `ofp_ack`, so a new red triangle is never locked out.
- NOTAM item D schedules are checked inside the role/FIR window (+max delay) when known, whole flight only as fallback, so a daily closure at an alternate never matches while the aircraft is elsewhere.
- AIP SUP NOTAMs with a resolved boundary skip the AIP-SUP manual step and are graded by geometry; flow control/CTOT/FPL-filing (QPF/QPO) without hard content is BRIEFING INFO.
- Single item-E coordinates (`source: e-field` dots, e.g. balloon release points) off the flight's own airports are measured against the track with the corridor and count as an identified area; the Q-line centre pin never does, so unbounded centres stay manual.
- Track-mode "Lọc notam tracking chuyến" grades every in-scope NOTAM with `port/notam_assess.ts` (five levels, tri-state gates, per-role time windows configurable from the client `cfg`); `dropped` holds only NO IMPACT so CRITICAL/manual items are never hidden. NOTAMs with closure/restricted-airspace content are re-assessed with soft rules (comms/navaid/lights/admin) skipped and the most severe level wins; unresolved area boundaries set `unidentified_area` for the blinking label, except aerodrome ground NOTAMs (`isAerodromeGround`: Q-code M/F/L or pure scope A surface text, no airspace/route content), which have no boundary by nature and are graded by what they close even when citing an AIP SUP. The label also requires airspace-area content (`isAirspaceAreaNotam`: restricted/warning text or QR/QW/QA-area Q-codes); ATS route lists (`atsRouteList`, graded against FPL tokens: in route NOTAMs — route Q-code, route wording or FIX-AWY-FIX chain — every designator token is scanned, skipping coordinates, NOTAM refs, aircraft types and taxiway/stand names; a route NOTAM is dropped only when no listed route or named fix is flown, and `spatialMatch` re-checks every route-type NO IMPACT the same way so one segment/navaid check never clears the rest), flow/procedure and navaid NOTAMs are never unidentified areas. Domestic tune keeps the legacy `tuneWhy` rules.
- AviWeb EOBT check runs only on the manual "Check ATC avi" button; never auto-trigger `vAviAutoCheck` when CHG/DLA cells render (user turned the background run off in V 5.19).
- FORM MNL resolves the day's CFP server-side via `port/formmnl_plan.ts`: Crewlist local date+ETD → real UTC ETD, IATA→ICAO, then a unique FliteBrief `plan_no` by flight/route/±6h before scanning JetPlan Dispatch; JetPlan pages are verified by their `callsign` input, so another day's plan is never used.
- NOTAM tracking and tune look up the sector through `findOperationalFlightById` (one shared small catalogue, one fresh retry on miss); never widen to multi-week FliteBrief reads, since the −6/+24 clip discards them and separate catalogue sizes split the cache.
- Compare batch "Tất cả (n)" lives in `port/cmp_batch.ts`: execution re-finds pending cells by sector and calls each existing handler sequentially; Ack all calls only selected cells' `_cmpAck`, never operational handlers or Verify, to preserve change-scoped acknowledgement. Drag ticks use an original-state contiguous range; modal design imports only global `--batch-*` tokens. Verify waits for job start/end via `cmpVerifyWait` because its job id arrives late.
- File-add defaults live in browser-safe `port/notice_rules_default.ts`, shared by `attch.ts` and `src/lib/notices.ts`; `prefix_touches_alt` matches DEP/DEST/alternates by ICAO or prefix with `!XX` exclusions so both matchers agree.
- Manual airspace paste parses/measures in browser-safe `port/manual_area.ts` (inlined into the tool page by the shim, so functions stay self-contained) with UI in `src/tool/manual-area.js`; it accepts hemisphere-before/after, spaced DMS, decimal and Q-line coordinates (Q-line only when no other coordinates exist), and 1/2 points become a point/line measured like areas; pasted areas stay in sessionStorage and are measured against the current track using the configured corridor and altitude buffer, never fed into automatic assessment.
- Czech (LK) and Kazakhstan (UA) ENR 5.1/5.2 areas are a bundled snapshot (`data/aip_enr_extra.json`) merged into `aip_enr_catalog.ts`, regenerated by `scripts/gen_aip_enr_extra.py` from the official eAIP tables; border-following boundaries are skipped, composite Z areas keep every part.
- Romania (LR, ENR 5.1/5.2 PDFs) and Hungary (LH, ENR 5.1/5.2/5.5 eAIP) areas are bundled snapshots (`data/aip_enr_lr.json`, `aip_enr_lh.json`) from `scripts/gen_aip_enr_lr.py` / `gen_aip_enr_lh.py`; lateral limits stop at the first vertical/activity line so remark coordinates never join a ring, and NOTAM mentions resolve FIR-scoped with zero-padding variants or all sub-areas of a parent name.
- Russia (UH/UL/UN/UR/US/UU/UW) ENR 5.1 areas are a bundled snapshot (`data/aip_enr_ru.json`, one shared source header) regenerated by `scripts/gen_aip_enr_ru.py` from the caica.ru PDF via `pdftotext -bbox` column positions; arcs, ellipses, stacked circles and route corridors are computed from their published definitions, state-border boundaries are skipped, and Russian prefixes resolve in any Russian FIR because subregions span FIR codes.
- Track/fleet NOTAM places pass through `dedupeAirportFirNotams` (port/notam_check.ts) after fetching: a NOTAM listed under both an airport and a FIR (shared ICAO such as UNNT) keeps one copy — airspace/ATM/warning Q-subjects under the FIR, aerodrome ones under the airport — so counts, hits and map labels are not doubled.
- OFP route-name hits (`ofpNamedHits`) pass track points through `port/route_name_scope.ts`: an airway/fix name flown only in another FIR or farther than the NOTAM radius + margin from its Q-line centre is a different route (identifiers repeat across regions, e.g. A464 Australia/Singapore); unknown positions keep the warning so nothing is hidden without evidence.
- Compare filter changes start `runCompare` immediately through `port/cmp_dsp_fast.ts` (DSP/callsign/route/REG/window handlers) instead of waiting for the board and 2-day catalogue reads; `loadFlights` skips its own Compare read only for the same scope started within a minute, and fresh-OFP refreshes always run.
- Compare sync checks after a Crewlist change send all changed flights on the current (DSP-filtered) Compare table to `fbreg` in chunks of 20 with one fresh FliteBrief read per chunk; the upload starts the shared Crewlist diff early and the table render reuses it, so later flights never queue behind per-flight reads.
- En-route alternate (RALT) NOTAM windows come from the OFP ETP table via `parseEtpAltTimes` (ETD + TIME TO ETP + TIME TO ALT, min/max over every ETP pair naming the airport) ± `enrt_alt_before/after`; whole-flight ETD→ETA is only the fallback when the table is missing, so distant-time NOTAMs at alternates are not over-graded.
- Storm overlays (JTWC KML and JMA) pass through `pacificLongitudes`/the JMA `point()` shift in `port/wx_overlay.ts`/`port/storms.ts`: each shape is unwrapped to continuous longitudes and western-Pacific shapes (< −90°) move by +360°, so tracks and danger swaths crossing 180° never stretch across the Asia-centred map.
- Track hits set `eta_ok` only when both B/C and the D) schedule (`notamDActiveNear`, same ±2h pass-time pad) are active; the page TRACKING-HIT override never lifts a NO IMPACT whose reason is a time/D) rejection, so near-track NOTAMs off-schedule are not forced CRITICAL.
- `notamGeoms` itself resolves named ENR 5.1 areas through `aip_enr_catalog` (scoped to the NOTAM FIR) and the track filter request keeps `sup_geoms`; `unidentified_area` is set only when no non-dot boundary resolves, so a drawn catalogue area is measured instead of flagged.
- AIMS Crewlist download lives only in `src/lib/tool/aims.server.ts` (pure parsing in `port/aims_report.ts`): it reuses the dispatcher's own saved DAYREP settings with only the date range replaced, keeps cookies in service-role-only `user_credentials.aims_cookies`, and the page loads the returned XLSX through the normal Crewlist upload so every downstream check stays identical. Auto-check (`/api/aims/watch`, pure diff in `port/aims_watch.ts`) diffs the fresh export against the user's current Crewlist via `xlsdiff`, counts added/removed sectors only for the same AIMS range, and returns the file only when it must be loaded; one browser tab leads polling via a localStorage lock so tabs never multiply AIMS logins.
- OFP alternate routes (`port/ofp_alt_routes.ts`): when JetPlan "ROUTE TO FIRST/SECOND/T/O ALTERNATE" headings exist, only they open ALT blocks (ending at the alternate ELEV line) — ETP/ALTERNATE DATA/ENROUTE ALT summaries otherwise turn the main route into ALT1.
- MET weather-site logins come only from the `MET_ACCOUNTS_JSON` secret, passed into `port/metwx.ts` by the handler, so credentials never live in source.
- TAF refresh fills gaps from NOAA AWC via `port/taf_awc.ts` (global cache files, one request each): MET TSN stays primary, NOAA replaces only TSN NIL records anywhere and adds unlisted airports only in `AWC_ADD_PREFIXES`, and still-NIL airports get a recent METAR for hover only — NOAA failure never blocks the TSN snapshot.
- Japan ENR 5.2 (JSDF Area 1–9/A–U) and ENR 5.3 (HK/TH/KK/CK/CS/KS/SM n-n) are a bundled snapshot (`data/aip_enr_jp.json`) regenerated by `scripts/gen_aip_enr_jp.py` from the AIP Japan PDFs; only numbered points are used (arcs as chords), and names resolve only inside RJ/RO FIRs, a bare letter/number drawing all its published sub-areas.
- AIP SUP portal-account errors (missing/invalid `AIP_ACCOUNTS_JSON`) are never cached, so fixing the secret takes effect on the next check; SUP coordinate lists stop at the first repeated vertex because map labels repeat the table.
- Japan SUP numbered-point areas parse first in `port/aip_sup.ts` (`parseJapanLabelledAreas`): arc clauses ("minor arc … radius of 45NM of Kajiki VOR") bend that boundary segment around the published centre from bundled `data/jp_navaids.json` (GEN 2.5/ENR 4.1/AD 2.19, regenerated by `scripts/gen_jp_navaids.py`); unknown or inconsistent centres skip the area and obstacle footprints (`MAX nm`) are ignored, so an arc is never drawn as a whole circle.

- Track-mode tune treats every airport place in the flight's briefing package as an en-route alternate (`RALT`, never OUT-OF-SCOPE), timed by the closest track point to its Q-line centre; each assessment carries `window` (role window label) shown on the NOTAM card.
- Stand/partial-taxiway NOTAMs without runway content are NO IMPACT at DEP (stands only) and alternates (TALT/ALT/RALT); ARR keeps BRIEFING INFO, so planning lists stay focused on what affects the flight.
- Alternate airports (ALT/RALT) drop low obstacles (<1000 FT from E/G) and taxiway/stand/ground-manoeuvring NOTAMs before the AIP SUP step; tune reads the OFP EET only for FIR windows so D) schedules are checked against real FIR times.
- Obstacle/crane NOTAMs at destination and en-route alternates are NO IMPACT regardless of height unless they mention runway, minima or hard closures; `obstacleHeightFt` ignores ARP bearing/distance and radius metres.
- India ENR 5.2 TRA/TSA and ENR 5.3 balloon areas are a bundled snapshot (`data/aip_enr_in.json`, keys `INTRA503A`) regenerated by `scripts/gen_aip_enr_in.py`; TRA/TSA ids resolve only inside VA/VE/VI/VO FIRs, border/river-following and partial-arc boundaries are skipped.
- Airport info NOTAMs (wildlife/HX, AD beacon/QLB, chart/ERSA amendments, DEP/ARR obstacles without closure/declared-distance/minima change) are BRIEFING INFO via step 15c; the page TRACKING-HIT override applies only to NOTAMs with no assessment, so assessed NO IMPACT is never forced CRITICAL.
- Singapore ENR 5.1/5.2/5.3 areas (incl. sub-areas and WM areas published in AIP Singapore) are a bundled snapshot (`data/aip_enr_sg.json`) regenerated by `scripts/gen_aip_enr_sg.py` from the CAAS eAIP; WS/WM ids resolve across WSJC and WM FIRs, and boundaries following ATZ/coastline are skipped, never guessed.
- Thailand AIP SUPs (VT FIRs) are fetched live from the public CAAT eAIP via `th_eaip`, scanning the newest publication folders' eSUP index (non-AIRAC SUPs only appear there); `parse_thailand_sup_html` takes one ring per boundary cell and never uses a bracketed arc centre as a vertex — arcs are drawn only when both ends sit on the stated radius, else the chord.
- Thailand ENR 5.1/5.2/5.3 is a bundled snapshot (`data/aip_enr_th.json`) regenerated by `scripts/gen_aip_enr_th.py`; sub-areas use suffix keys (VTD30W2, VTD64N) and a named "AREA n" replaces its parent, while area designators (`VT D30W`, `VV R16`) are excluded from `atsRouteList` so danger areas are graded by geometry, not as unflown routes.
- Volcano NOTAMs (Q-code WW or volcanic/ash wording) are shaped in `notamGeomsText` via `volcanoGeoms`: each unchained point (or the Q centre) becomes a `VOLCANO_BUFFER_NM` circle, chained/bounded coordinates and explicit radii keep their published shape, so summit-only warnings are measured instead of left as pins.
- NOTAM map flashes of ATS routes (`nmFlashFleetNotam`/`nmFlashTrackNotam` in `src/tool/page.html`) are scoped to the issuing FIR country via `nmNotamCc` and clipped by `nmNotamRouteSegs`, because route names repeat across countries.
- tool-files retention lives in pure `port/file_retention.ts`, run hourly by cron route `/api/public/cron/cleanup-files` (admin client, cron secret) — workers cannot clean up after a session ends. Open-time cleanup trusts the server presence stamp (`files.alive@u:<uid>`), never browser storage, so reloads while online keep files; a new MEL split prunes the user's old VNAxxx.pdf on server and PC instead of age-based deletion.
- VIP movement NOTAMs are detected by browser-safe `port/notam_vip.ts` (inlined into the tool page for card labels); only destination arrivals whose ETA ± margin overlaps B)–C) get the `vip` summary section / `vip_hold` CRITICAL grade, so departures and off-window flights never warn.
- Check NOTAM quốc nội grades every fetched NOTAM against each domestic flight using its airport/FIR via `port/notam_fleet_assess.ts` (same `assessNotam` engine, client `cfg` from the check request); the most severe level is stamped on the NOTAM with the responsible flight in the reasons, so overview counters work without the hidden domestic tune button.
- Destination-TAF extra minutes come from `port/extra_wx.ts` with an editable `ExtraWxCfg` (layered key `extra_wx_cfg`, `/api/extra/cfg`), threaded explicitly into `taf.advise`; never keep it in module state, since Worker requests share modules across users.
- Route FPL suffix: STD UTC + route `kapli_time` < 1700Z picks KAPLI (fallback STD 1500 rule when blank) in `_suffix`, `lib/fpl.ts` and the page shim; keep all three identical.
- NOTAM ATS route rows in `verdictOf` count only hits with `eta_ok` (B–C/D at crossing) and FL ≤ ceiling + configured `alt_buffer_ft`; text-only route NOTAMs (no geometry hit) go through `namedRouteLive` (named fix pass time ±1h), and the fleet map flashes only flights whose verdict lists the NOTAM, so spatial/name matches never ignore time/altitude.
- TAF hover highlight uses `segmentsForWindow` over the same ETA ±1h window as `adviceForFlight`/`adviceWindow`, so lit groups always match the weather that drove the verdict.
- NOTAM delay grading: a hit reachable only after a delay up to `delay_buffer_minutes` (client Filter setting) is CRITICAL with the delay in its reasons; only longer delays are DELAY-ONLY. ATS Route rows accept listed segments with a coordinate end via `ats_segment_coord`, so buffered closures reach Thông tin chung and flash.
- PC helper AviWeb/OWA jobs carry the caller's saved login (`creds.server` env) in the job payload; the helper applies it only for that job (AviWeb via temporary `AVIWEB_USER/PASS` env) so a stale local `credentials.json` never overrides the web account.
- `pc_jobs` rows are transient delivery envelopes: a daily pg_cron job (`pc-jobs-cleanup-10d`) deletes finished rows past the retention window, because file/fetch payloads otherwise fill the database disk; `pc_jobs_new` is a deprecated empty staging table.
- SIGMET/VA map layers: server `GET /api/wx/sigmet` shapes NOAA AWC international SIGMETs via browser-safe `port/sigmet.ts` (region + expiry filter, repeated bulletin = FCST polygon); `src/tool/sigmet-layer.js` draws them and measures against the track with `window.__ma.check`, display-only and never fed into NOTAM assessment.
- Compare ATC quick message remembers a live Crewlist≠FliteBrief aircraft change per sector (`cmpRegMemory`, browser-local `cmp_regmem_v1`) and picks the kind via `cmpMsgKind`, so pushing the corrected CFP never downgrades CHG DLA to DLA; memory is keyed by sector ID + callsign (`cmpRegMemFind` migrates old STD keys) so a delay never drops it, and drops only when the Crewlist aircraft moves away from the remembered new tail. DLA comes from the FPL diff or, failing that, the Crewlist delay (`cmpDelayKind`: diff row or STD→ETD ≥15 min).
- Quick ATC messages pick times via `atcChg.msg_eobts`: header keeps the filed AviWeb EOBT (time-change kinds fall back to original STD, others to ETD) and DLA/CHG TIME/CHG DLA carry the current Crewlist ETD in UTC as the new time, so item 13 never repeats the old EOBT.
- En-route FIR NOTAMs capped below FL100 are dropped only when `lowEnroutePortDistNm` (NOTAM area to each DEP/ARR airport separately, Q-line circle fallback) exceeds the Filter setting `enroute_low_port_nm` (default `ENROUTE_LOW_PORT_NM`); near or unmeasurable areas continue through the normal altitude/time gates, because climb/descent crosses neighbouring FIRs below FL100.
- NOTAM map SkyVector tiles take edition/tile server from `/api/map/skyvector` (SkyVector init, 1h cache) with browser-safe `port/skyvector.ts` AIRAC fallback and a one-step-back retry when every tile 404s — never hardcode the edition, since it changes every 28 days.
- Singapore/Korea/Hong Kong/Malaysia AIP SUPs (WS/RK/VH/WM-WB FIRs) resolve through each portal's public SUP list (`loadSupIndex` in `aip_sup.server.ts`, newest packages merged, expired dropped) and the shared `parse_generic_sup_text`; obstacle-only SUPs, height-separated lists and waypoint tables never become areas, and Database → AIP SUP (`src/tool/aip-sup-db.js`, `/api/aipsup/*`) reads the same caches so the list and NOTAM matching never disagree.
- Outlook Web draft signatures are built server-side in browser-safe `port/mail_signature.ts` (banner bytes bundled in `data/mail_signature_banner.json`) and sent to the PC helper as `html` + `inline` cid attachments, because OWA REST never auto-appends signatures; helpers that ignore these fields still create the plain-text draft.
- Crew compare treats a FliteBrief sector with no working (non-DHD) crew as not yet assigned (`crewFbEmpty`, cell `fb_empty`, neutral icon), never a mismatch, so freshly pushed flights raise no ↻ Crew/batch action; the Ver-tab EFF batch previews each crew swap and skips sectors FliteBrief already matches.
- KHB typed PLD (`pldManual`) commits on every keystroke in `port/khb_payload.ts` and is skipped by Auto Rounding, its off-toggle and EST loads, so REQ exports exactly the typed PAY; regexes inside the shim template literal need `\\d`.
- TAF parsing in `port/taf.ts` treats Australian `INTER` like TEMPO via `isOverlayKind`; visibility readers drop RMK and DDHH/DDHH pairs so time groups or QNH values never become visibility bands.
- Route-name hits (`ofp_hits`, verdict ATS rows) take every designator from `atsRouteList` whatever the layout, and `routeNameRemote` keeps a name when the flight is inside the NOTAM FIR next to it (retired VVTS/VVNB aliased); FL-limit-only route NOTAMs (`port/route_fl_limit.ts`) give `soft` green ATS rows that never raise flight status, so level limits are visible without false alarms.
- Compare pop-up action buttons (CHG/DLA quick, ↻ Crew/⚠ REG sync, CFP REQ, Đổi BF) split on a real (isTrusted) click into Ack + main action via `cmpTwoOpen` in `port/cmp_sync.ts`; each button supplies `_cmpAck` storing a change-scoped ack, while batch/programmatic clicks still run the main handler directly. Red-triangle Verify has no Ack so OFP acknowledgement is never skipped.
