## Tool rules
- KHB and FPL/REQ share `port/cost_index_region.ts` for CI country fallback and explicit airport exceptions, preserving configured CI values. Countries come from the Airport Database ICAO map; unique IATA→ICAO codes are bundled from datasets/airport-codes (OurAirports), never guessed from timezone or prefix, to keep exports consistent.
- NOTAM missing/new quick-view uses `port/notam_change_popup.ts` through the HTML shim; retain PDF bodies and T-60 details alongside comparison state, and acknowledge only opened IDs to preserve later arrivals.
- Compare CREW/REG hover presentation lives in `port/cmp_crew_hover.ts`, separates Excel/FliteBrief without changing matching inputs, labels OFP fallback separately, and imports only its semantic token declarations from global CSS for the isolated tool document.
- KHB change markers reconcile the current/previous Crewlist through existing version reads in `khb_crew_sync`; refresh source identity and paint before optional history reads so history failure cannot block new data. Remapping retains prior source fields until reconciliation; repair old saved aircraft only with exact Crewlist diff evidence, preserve manual values on unchanged fields, never reinsert FPL history, and persist empty change maps.
- FPL quick-view reparents the live `wrapVer` into a dialog and restores it on close; acknowledge only a successfully displayed filename so unseen newer revisions remain pending.
- KHB airport hover composes existing limits and TAF in `port/khb_airport_hover.ts` after the tool-page patches; exempt these cells from generic title tips so weather stays visible.
- NOTAM summaries use per-flight `verdictOf`/`fleetVerdict` in `port/notam_verdict.ts`, not raw map hit counts (those include distant/unresolved/above-ceiling areas). Every FliteBrief NOTAM tracking/fleet place is filtered through `apply24h` before enrichment and counting — the upstream payload is ALL, not the portal's 24H selection.
- GD printing commits paper/orientation, joins disjoint print areas, sets an explicit Zoom measured from the print range (min 18pt margins) and verifies one page via Excel's own PDF export before printing — RICOH drivers ignore FitToPages and Excel's page count can be stale.
- Australian DAH is a bundled snapshot (`data/au_dah.json`: rings + fir + vert) regenerated from the DAH PDF via `parse_australia_dah_areas`; NOTAMs resolve sector names with `au_dah_names_in_text` scoped to the NOTAM FIR, and boundaries following coast/FIR lines are skipped rather than guessed.
- AIP SUP/DAH rings/hours are fetched in `src/lib/tool/aip_sup.server.ts` (parsers in `port/aip_sup.ts`, cache in app_settings `aip_sup:*`), attached as `notam.sup_geoms` by the Check NOTAM handler — NOTAM text often only names the SUP area. JP ENR/KR KOCA use national parsers and country caches; client fixes preserve server arcs and separate areas.
- Named ENR 5.1 areas (WS/WM/WB/VV/VT/VI/RK…) resolve first from bundled `src/lib/tool/data/aip_enr_rings.json` via `port/aip_enr_catalog.ts`; tracking ATS routes use bundled `ats_routes.json` via `/api/notam/vnchart` — live AIP fetches are unreliable in a request.
- Special limits are structured rows (`rule`/`acs`/`apts`) evaluated by browser-safe `src/lib/special-rules.js`, shared by the tool page (via shim) and `port/limits_check.ts`; aircraft groups live in admin-only `limits.acgroups`. Legacy free-text rows keep the old parser.
- Allowed-aircraft LIMIT success is presentation-only via `srOnlyAircraftDisplay` and the tool-page shim; never place success in operational warning arrays, and keep other warnings higher priority.
- Aircraft allowlist airport rules evaluate destination only in the shared special-rules evaluator; departure and alternate restrictions remain independent to prevent unrelated-route warnings.
- Red-triangle verify lives only in the Compare VERIFY column: `port/cmp_validation.ts` prepends a `.cmp-vf` tick wired to `csQuickVerify` (with an `onDone` that clears `ofp_ack` and calls `vMarkDone`), so the flight board callsign cell stays free of write actions.
- Track-mode "Lọc notam tracking chuyến" grades every in-scope NOTAM with `port/notam_assess.ts` (five levels, tri-state gates, per-role time windows configurable from the client `cfg`); `dropped` holds only NO IMPACT so CRITICAL/manual items are never hidden. NOTAMs with closure/restricted-airspace content are re-assessed with soft rules (comms/navaid/lights/admin) skipped and the most severe level wins; unresolved area boundaries set `unidentified_area` for the blinking label. Domestic tune keeps the legacy `tuneWhy` rules.
- AviWeb EOBT check runs only on the manual "Check ATC avi" button; never auto-trigger `vAviAutoCheck` when CHG/DLA cells render (user turned the background run off in V 5.19).
- FORM MNL resolves the day's CFP server-side via `port/formmnl_plan.ts`: Crewlist local date+ETD → real UTC ETD, IATA→ICAO, then a unique FliteBrief `plan_no` by flight/route/±6h before scanning JetPlan Dispatch; JetPlan pages are verified by their `callsign` input, so another day's plan is never used.
- NOTAM tracking and tune look up the sector through `findOperationalFlightById` (one shared small catalogue, one fresh retry on miss); never widen to multi-week FliteBrief reads, since the −6/+24 clip discards them and separate catalogue sizes split the cache.
- Compare batch "Tất cả (n)" header buttons live in `port/cmp_batch.ts`: they re-find each pending cell by sector and run its existing handler sequentially after one confirmation, so batch runs keep every per-flight check; Verify waits for job start then end via `cmpVerifyWait` because the job id arrives only after the request returns.
- File-add defaults live in browser-safe `port/notice_rules_default.ts`, shared by `attch.ts` and `src/lib/notices.ts`; `prefix_touches_alt` matches DEP/DEST/alternates by ICAO or prefix with `!XX` exclusions so both matchers agree.
- Manual airspace paste parses/measures in browser-safe `port/manual_area.ts` (inlined into the tool page by the shim) with UI in `src/tool/manual-area.js`; pasted areas stay in sessionStorage and are measured against the current track using the configured corridor and altitude buffer, never fed into automatic assessment.
- Czech (LK) and Kazakhstan (UA) ENR 5.1/5.2 areas are a bundled snapshot (`data/aip_enr_extra.json`) merged into `aip_enr_catalog.ts`, regenerated by `scripts/gen_aip_enr_extra.py` from the official eAIP tables; border-following boundaries are skipped, composite Z areas keep every part.
- Russia (UH/UL/UN/UR/US/UU/UW) ENR 5.1 areas are a bundled snapshot (`data/aip_enr_ru.json`, one shared source header) regenerated by `scripts/gen_aip_enr_ru.py` from the caica.ru PDF via `pdftotext -bbox` column positions; arcs, ellipses, stacked circles and route corridors are computed from their published definitions, state-border boundaries are skipped, and Russian prefixes resolve in any Russian FIR because subregions span FIR codes.
- Track/fleet NOTAM places pass through `dedupeAirportFirNotams` (port/notam_check.ts) after fetching: a NOTAM listed under both an airport and a FIR (shared ICAO such as UNNT) keeps one copy — airspace/ATM/warning Q-subjects under the FIR, aerodrome ones under the airport — so counts, hits and map labels are not doubled.
- OFP route-name hits (`ofpNamedHits`) pass track points through `port/route_name_scope.ts`: an airway/fix name flown only in another FIR or farther than the NOTAM radius + margin from its Q-line centre is a different route (identifiers repeat across regions, e.g. A464 Australia/Singapore); unknown positions keep the warning so nothing is hidden without evidence.
