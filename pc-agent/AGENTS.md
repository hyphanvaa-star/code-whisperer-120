# pc-agent notes
- CHG/DLA runs through `tool/aviweb_messages.py`, wrapping the supplied sender without route selectors; same-row DOF/DEP/ARR (Vaadin `v-table-header-cell` captions, else in-order row content where the cell right after DEST is the row's first date and equals DOF; cells are normalised only by dropping the callsign icon prefix, an aerodrome's bracketed city and a date's trailing clock) and complete-table checks gate each Submit, after narrowing Processed by callsign when the search box exists. `manual_submit` shows Chrome and never clicks the final Submit: only an operator click on that button followed by the form closing counts as sent. Virtualized candidate sets fail closed, no write retries or certificate bypass; credentials are job-scoped.

- `background.py` runs hidden (pythonw, session mutex, stop event). Bootstrap picks the first writable dir (D:\.TroLyPC, then LOCALAPPDATA), stages+compiles `app.zip` before overwriting, keeps runtime files; the agent only notes newer `manifest.json` versions (never exits mid-shift); updates install at start-up or when the user clicks the orange AGENT label (local `/update` only sets a flag; the main loop installs before claiming the next job, so nothing is cut mid-run and the web never sees "busy"; the web quietly retries "busy" from helpers ≤6.15). Bootstrap writes `update_status.json`, reported in heartbeats so failures show on the web. A separate heartbeat thread (`heartbeat_only`, never claims jobs) keeps the dot green during long jobs. AGENT dot polls `GET /api/pc/status`. `pack.py` is the explicit allowlist for all `public/agent` files.
- Chrome cleanup (`tool/chrome_drv.py`) only kills processes whose `--user-data-dir` equals the tool profile and starts with `SAFE_START_FLAGS`; never `taskkill /IM chrome.exe`, which closes the user's own Chrome.
- Job routing: the tool page stores the local helper's machine id (`aid` from /pair) in the `pc_aid` cookie, so `_aid` jobs run only on that PC; `_uid` jobs go to that account's helper; same-IP unpaired helpers take them only while the owner's helper is offline (office NAT shares one IP). Claims return only rows actually flipped to running so two PCs never run one job.
- PC helper tool discovery prefers bundled `app/tool` and accepts both source `.py` and sourceless `.pyc` for required modules; discovery errors stay noninteractive so background retries cannot open folder prompts.
- PC helper: frozen C:/shared D: machines use OneDrive `Bat-Tro-Ly.vbs` → `/agent/bootstrap.py`, which repairs and hash-checked self-updates code (old kept on failure); rebuild with `python3 pc-agent/pack.py`. Details in `pc-agent/AGENTS.md`.
- Outlook Web `ensure_session` always starts Chrome headless; only when the Microsoft login page persists (`_should_show_login`: 15s grace or visible MFA text) does it reopen the same profile visibly so the user can confirm, then quits. Silent token refresh passes `show_on_login=False` so background renewals never pop a window. On "Pick an account" it clicks the saved email's tile, else "Use another account" (shared PCs cache other users), gated on picker text so the password page's email banner is never clicked.
- Distribution is a single `Bat-Tro-Ly.vbs` downloaded from the AGENT dot; it fetches `bootstrap.py`, which installs `app.zip` and libraries. No ZIP installer or extra launcher scripts, so shared office PCs stay clean.
