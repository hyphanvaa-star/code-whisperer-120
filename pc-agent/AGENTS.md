# pc-agent notes

- `background.py` runs hidden (pythonw, session mutex, stop event). Bootstrap picks the first writable dir (D:\.TroLyPC, then LOCALAPPDATA), stages+compiles `app.zip` before overwriting, keeps runtime files; the agent only notes newer `manifest.json` versions (never exits mid-shift); updates install at start-up or when the user clicks the orange AGENT label (local `/update`, refused while a job runs). Bootstrap writes `update_status.json`, reported in heartbeats so failures show on the web. A separate heartbeat thread (`heartbeat_only`, never claims jobs) keeps the dot green during long jobs. AGENT dot polls `GET /api/pc/status`. `pack.py` is the explicit allowlist for all `public/agent` files.
- Chrome cleanup (`tool/chrome_drv.py`) only kills processes whose `--user-data-dir` equals the tool profile and starts with `SAFE_START_FLAGS`; never `taskkill /IM chrome.exe`, which closes the user's own Chrome.
- Job routing: the tool page stores the local helper's machine id (`aid` from /pair) in the `pc_aid` cookie, so `_aid` jobs run only on that PC; `_uid` jobs go to that account's helper; same-IP unpaired helpers take them only while the owner's helper is offline (office NAT shares one IP). Claims return only rows actually flipped to running so two PCs never run one job.
- PC helper tool discovery prefers bundled `app/tool` and accepts both source `.py` and sourceless `.pyc` for required modules; discovery errors stay noninteractive so background retries cannot open folder prompts.
- PC helper: frozen C:/shared D: machines use OneDrive `Bat-Tro-Ly.vbs` → `/agent/bootstrap.py`, which repairs and hash-checked self-updates code (old kept on failure); rebuild with `python3 pc-agent/pack.py`. Details in `pc-agent/AGENTS.md`.
